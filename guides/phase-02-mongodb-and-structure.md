# Phase 2 Manual — MongoDB & Structure

**Duration:** 2–3 weeks  
**Prerequisite:** Phase 1 complete

Phase 1 data vanishes on restart. Phase 2 gives Desklog **persistent storage** with MongoDB and reorganizes code into **layers** so each part has one job. This manual explains every concept and instruction you need — read it in order.

---

## 0. What changes in this phase

| Before (Phase 1) | After (Phase 2) |
|------------------|-----------------|
| Data in maps in RAM | Data in MongoDB on disk |
| Logic mixed in handlers | handler → service → repository |
| String IDs | MongoDB `ObjectID` internally, string in JSON |
| Restart = data loss | Restart = data remains |

Your HTTP routes stay almost the same. You swap the storage layer and split responsibilities.

**Same habit as Phase 1:** still follow [The endpoint recipe](./the-endpoint-recipe.md). This phase only changes *what* sits under the handler.

| Recipe step | Phase 1 | Phase 2 |
|-------------|---------|---------|
| Contract | method / path / JSON / statuses | Same routes; IDs become ObjectID hex strings in JSON |
| Model | `internal/model` + JSON tags | Add BSON tags; `primitive.ObjectID` for IDs |
| Data | `internal/store` (maps) | `internal/repository` (MongoDB) |
| Business rules | Mostly in handler | `internal/service` |
| Handler | parse → store → respond | parse → **service** → respond (no Mongo imports) |
| Wire | `main` creates store | `main` creates client, repos, services, handlers |
| Verify | curl | curl + restart server (data must persist) |

When you migrate or add an endpoint: **contract → model → repository method → service method → handler → wire → curl**. Do not put MongoDB calls in handlers.

## 1. Layered architecture

### Why layers exist

A handler that talks directly to MongoDB becomes impossible to test without a database and impossible to change storage without rewriting HTTP code. **Layers** separate concerns:

```
Client (curl, browser, mobile app)
        ↓ HTTP
   handler     — speaks HTTP only: parse request, write response
        ↓
   service     — business rules: "project must exist before creating task"
        ↓
   repository  — database only: queries, inserts, updates
        ↓
   MongoDB
```

**Rule:** dependencies point inward. Handlers know services. Services know repository interfaces. Repositories know MongoDB. Never the reverse.

### Package layout

```
cmd/api/main.go                 # wire everything, start server
internal/model/                 # structs (domain types)
internal/repository/            # MongoDB access
internal/service/               # business logic
internal/handler/               # HTTP handlers
```

`internal/` means other projects cannot import these packages — they are private to Desklog.

### Dependency injection (without a framework)

`main` creates concrete objects and passes them down:

```go
projectRepo := repository.NewProjectRepo(db)
taskRepo := repository.NewTaskRepo(db)
taskSvc := service.NewTaskService(projectRepo, taskRepo)
taskHandler := handler.NewTaskHandler(taskSvc)

http.HandleFunc("POST /projects/{id}/tasks", taskHandler.Create)
```

No global variables for DB or services. Pass dependencies explicitly.

## 2. MongoDB fundamentals

### What MongoDB is

MongoDB is a **document database**. Data is stored as **documents** (JSON-like **BSON** objects) grouped in **collections** (like tables in SQL, but schema-flexible).

| SQL concept | MongoDB equivalent |
|-------------|-------------------|
| Database | Database |
| Table | Collection |
| Row | Document |
| Column | Field |
| Primary key | `_id` (usually ObjectId) |
| JOIN | `$lookup` in aggregation (Phase 4) or application-level reference |

### Documents and references

Desklog uses **references** between documents:

- A **task** has `project_id` pointing to a **project**'s `_id`
- Documents live in separate collections (`projects`, `tasks`)

**Alternative:** embed tasks inside project document. We do not do this because tasks are queried independently (`GET /tasks/{id}`) and lists can grow large.

### ObjectId

MongoDB's default `_id` type is **ObjectId** — 12 bytes, unique, generated by driver or server.

In Go: `primitive.ObjectID` from `go.mongodb.org/mongo-driver/bson/primitive`

- Store as `ObjectID` in BSON
- Expose as hex string in JSON API: `"507f1f77bcf86cd799439011"`

```go
id := primitive.NewObjectID()                    // generate
id, err := primitive.ObjectIDFromHex(idStr)      // parse from URL
id.Hex()                                         // string for JSON
```

Invalid hex string when parsing → treat as bad request (`400`) or not found (`404`) — pick one, stay consistent.

### BSON vs JSON

| | JSON | BSON |
|---|------|------|
| Used for | API responses, API requests | MongoDB storage |
| Types | string, number, object, array | + Date, ObjectId, binary, etc. |

Go structs carry both tag types:

```go
type Project struct {
	ID   primitive.ObjectID `bson:"_id,omitempty" json:"id"`
	Name string             `bson:"name" json:"name"`
}
```

- `bson:"_id,omitempty"` — MongoDB field name; omit when empty on insert so server generates ID
- `json:"id"` — API field name

## 3. Running MongoDB locally

**Context:** Your Go app is a client. MongoDB must run separately, like a separate process listening on port 27017.

### Docker (recommended)

```bash
docker run -d --name desklog-mongo -p 27017:27017 mongo:7
```

- `-d` — background
- `-p 27017:27017` — expose MongoDB port to your machine
- `mongo:7` — official image, version 7

Verify connection:

```bash
docker exec -it desklog-mongo mongosh
```

In mongosh: `show dbs` — you should see admin/local.

### Connection string

Format: `mongodb://host:port`

Local default: `mongodb://localhost:27017`

Your app reads:

```
MONGODB_URI=mongodb://localhost:27017
MONGODB_DATABASE=desklog
PORT=8080
```

**Never hard-code** the URI in source. Use `os.Getenv`. If `MONGODB_URI` is empty at startup, log a clear error and exit.

## 4. MongoDB Go driver

### Install

```bash
go get go.mongodb.org/mongo-driver/mongo
go get go.mongodb.org/mongo-driver/bson
go get go.mongodb.org/mongo-driver/mongo/options
```

### Connect and ping

**Context:** Connection is expensive. Create **one** `mongo.Client` at startup, reuse for the app lifetime. The driver pools connections internally.

```go
ctx, cancel := context.WithTimeout(context.Background(), 10*time.Second)
defer cancel()

clientOptions := options.Client().ApplyURI(os.Getenv("MONGODB_URI"))
client, err := mongo.Connect(ctx, clientOptions)
if err != nil {
	log.Fatal("connect:", err)
}

if err := client.Ping(ctx, nil); err != nil {
	log.Fatal("ping:", err)
}

db := client.Database(os.Getenv("MONGODB_DATABASE"))
```

On shutdown (Phase 5): `client.Disconnect(ctx)`.

### context.Context — why every DB call has it

**Context** carries:

- **Deadline** — cancel after timeout
- **Cancellation** — stop when client disconnects
- **Request-scoped values** (used in Phase 3 for user ID)

Every repository method signature:

```go
func (r *ProjectRepo) GetByID(ctx context.Context, id primitive.ObjectID) (model.Project, error)
```

Handlers pass `r.Context()` from the HTTP request. This connects HTTP lifecycle to database operations.

### Collection handle

Repositories hold a reference to one collection:

```go
type ProjectRepo struct {
	col *mongo.Collection
}

func NewProjectRepo(db *mongo.Database) *ProjectRepo {
	return &ProjectRepo{col: db.Collection("projects")}
}
```

## 5. CRUD operations in MongoDB

### InsertOne — create

```go
func (r *ProjectRepo) Create(ctx context.Context, p model.Project) (model.Project, error) {
	p.ID = primitive.NewObjectID()
	now := time.Now().UTC()
	p.CreatedAt = now
	p.UpdatedAt = now

	_, err := r.col.InsertOne(ctx, p)
	return p, err
}
```

MongoDB creates the document in the `projects` collection. `InsertOne` returns `InsertedID` if you need it.

### FindOne — get by ID

```go
func (r *ProjectRepo) GetByID(ctx context.Context, id primitive.ObjectID) (model.Project, error) {
	var p model.Project
	err := r.col.FindOne(ctx, bson.M{"_id": id}).Decode(&p)
	if err != nil {
		if errors.Is(err, mongo.ErrNoDocuments) {
			return model.Project{}, ErrNotFound
		}
		return model.Project{}, err
	}
	return p, nil
}
```

`bson.M` is `map[string]interface{}` — shorthand for filters.

`mongo.ErrNoDocuments` means no match — map to your `ErrNotFound`, then HTTP 404. Do not return 500 for missing data.

### Find — list

```go
func (r *ProjectRepo) List(ctx context.Context) ([]model.Project, error) {
	cursor, err := r.col.Find(ctx, bson.M{})
	if err != nil {
		return nil, err
	}
	defer cursor.Close(ctx)

	var projects []model.Project
	if err := cursor.All(ctx, &projects); err != nil {
		return nil, err
	}
	return projects, nil
}
```

Always `defer cursor.Close(ctx)`.

Filter tasks by project:

```go
filter := bson.M{"project_id": projectID}
cursor, err := r.col.Find(ctx, filter)
```

### UpdateOne — partial update

Use `$set` to update specific fields without replacing the whole document:

```go
update := bson.M{
	"$set": bson.M{
		"name":        name,
		"description": description,
		"updated_at":  time.Now().UTC(),
	},
}
res, err := r.col.UpdateOne(ctx, bson.M{"_id": id}, update)
if res.MatchedCount == 0 {
	return ErrNotFound
}
```

### DeleteOne / DeleteMany

```go
// delete one project
res, err := r.col.DeleteOne(ctx, bson.M{"_id": id})

// delete all tasks for a project
_, err := r.col.DeleteMany(ctx, bson.M{"project_id": projectID})
```

## 6. Repository interfaces

**Context:** Services depend on **interfaces**, not concrete MongoDB types. Tests can use fakes. Swapping storage is possible.

```go
type ProjectRepository interface {
	List(ctx context.Context) ([]model.Project, error)
	GetByID(ctx context.Context, id primitive.ObjectID) (model.Project, error)
	Create(ctx context.Context, p model.Project) (model.Project, error)
	Update(ctx context.Context, p model.Project) (model.Project, error)
	Delete(ctx context.Context, id primitive.ObjectID) error
}
```

`MongoProjectRepo` implements this interface implicitly (Go has no `implements` keyword — if methods match, it satisfies the interface).

Define `ErrNotFound` as a package-level sentinel:

```go
var ErrNotFound = errors.New("not found")
```

Services compare with `errors.Is(err, repository.ErrNotFound)`.

## 7. Service layer — business rules

**Context:** Services orchestrate repositories and enforce rules that are not HTTP-specific and not SQL-specific.

### Example: create task

```go
func (s *TaskService) Create(ctx context.Context, projectID primitive.ObjectID, title, status string) (model.Task, error) {
	// Rule: project must exist
	if _, err := s.projectRepo.GetByID(ctx, projectID); err != nil {
		return model.Task{}, err
	}

	if title == "" {
		return model.Task{}, &ValidationError{Field: "title", Message: "required"}
	}
	if status == "" {
		status = "todo"
	}

	task := model.Task{
		ProjectID: projectID,
		Title:     title,
		Status:    status,
	}
	return s.taskRepo.Create(ctx, task)
}
```

### Example: delete project with cascade

MongoDB does not enforce foreign keys. Deleting a project without deleting its tasks leaves **orphans**.

**Service responsibility:**

```go
func (s *ProjectService) Delete(ctx context.Context, id primitive.ObjectID) error {
	if err := s.taskRepo.DeleteByProjectID(ctx, id); err != nil {
		return err
	}
	return s.projectRepo.Delete(ctx, id)
}
```

Order: delete children first, then parent.

**Transactions (optional):** MongoDB multi-document transactions require a replica set. For local single-node dev, sequential deletes are acceptable. Document this in README.

## 8. Handler layer — map errors to HTTP

**Context:** Handlers translate domain errors to status codes. One mapping table for the whole app:

| Error | HTTP status |
|-------|-------------|
| `ErrNotFound` | 404 |
| `ValidationError` | 400 |
| Duplicate key (MongoDB code 11000) | 409 |
| Anything unexpected | 500 (log full error, return generic message) |

```go
func (h *ProjectHandler) Get(w http.ResponseWriter, r *http.Request) {
	id, err := primitive.ObjectIDFromHex(r.PathValue("id"))
	if err != nil {
		writeError(w, http.StatusBadRequest, "invalid id")
		return
	}

	project, err := h.svc.GetByID(r.Context(), id)
	if errors.Is(err, repository.ErrNotFound) {
		writeError(w, http.StatusNotFound, "project not found")
		return
	}
	if err != nil {
		log.Println(err)
		writeError(w, http.StatusInternalServerError, "internal error")
		return
	}

	w.Header().Set("Content-Type", "application/json")
	_ = json.NewEncoder(w).Encode(project)
}
```

Handlers stay thin — no `if title == ""` business logic if the service already validates.

## 9. Indexes

### What indexes do

Without an index, MongoDB scans every document (**collection scan**). Fine for 50 documents; slow at 5 million.

An **index** is a sorted structure (like a book index) that lets MongoDB find documents by field value quickly.

### Indexes for Desklog

Create `scripts/indexes.js`:

```javascript
db = db.getSiblingDB('desklog');

db.projects.createIndex({ name: 1 });
db.tasks.createIndex({ project_id: 1 });
db.tasks.createIndex({ project_id: 1, status: 1 });
```

Run via mongosh:

```bash
docker exec -i desklog-mongo mongosh < scripts/indexes.js
```

Or create indexes in Go at startup (idempotent):

```go
_, _ = col.Indexes().CreateOne(ctx, mongo.IndexModel{
	Keys: bson.D{{Key: "project_id", Value: 1}},
})
```

### Unique index (stretch)

```javascript
db.projects.createIndex({ name: 1 }, { unique: true });
```

Duplicate insert returns error code **11000**. Catch in repository or service → HTTP 409 Conflict.

## 10. JSON API with ObjectID

Clients send and receive IDs as strings. Internally you use `ObjectID`.

**Option A — custom JSON marshaling on model** (advanced)

**Option B — response DTO** (clearer for learning)

```go
type ProjectResponse struct {
	ID          string    `json:"id"`
	Name        string    `json:"name"`
	Description string    `json:"description,omitempty"`
	CreatedAt   time.Time `json:"created_at"`
	UpdatedAt   time.Time `json:"updated_at"`
}

func toProjectResponse(p model.Project) ProjectResponse {
	return ProjectResponse{
		ID:          p.ID.Hex(),
		Name:        p.Name,
		// ...
	}
}
```

Pick one approach and use it for all entities.

## 11. Build order for this phase (recipe order)

Work **one vertical slice at a time** (e.g. `POST /projects` end-to-end), then the next route. Do not rewrite every file before testing.

| Step | Recipe | What to build | Where |
|------|--------|---------------|-------|
| 1 | Model | Structs with BSON + JSON tags | `internal/model/` |
| 2 | Wire (partial) | Mongo client from env (`MONGODB_URI`, DB name) | `cmd/api/main.go` |
| 3 | Data | Project repository CRUD | `internal/repository/` |
| 4 | Business | Project service | `internal/service/` |
| 5 | Handler + wire | Migrate **one** project endpoint; curl it | `internal/handler/` + `main` |
| 6 | Repeat 3–5 | Task repo (incl. ListByProject, DeleteByProjectID) → service → handlers | same packages |
| 7 | Data extras | Indexes | scripts / startup |
| 8 | Verify | Restart server — data still there | curl + mongosh |
| 9 | Docs | Mongo setup in README | `README.md` |

**Reminder:** for each endpoint, fill the recipe card in [the-endpoint-recipe.md](./the-endpoint-recipe.md) before coding.

## 13. Common mistakes

| Mistake | Consequence | Fix |
|---------|-------------|-----|
| MongoDB calls in handlers | Untestable, tangled code | Repository only |
| Ignoring `ctx` | Cannot timeout/cancel | Pass `r.Context()` |
| String `_id` in BSON | Type mismatches, slow queries | Use `primitive.ObjectID` |
| No cascade delete | Orphan tasks | `DeleteMany` in service |
| `ErrNoDocuments` → 500 | Wrong semantics | Map to 404 |
| New client per request | Connection exhaustion | One client in `main` |
